# T-Lab — دليل تجربة Windows 11 على قاعدة MySQL منفصلة

> **النوع: نسخة تجريبية (SANDBOX PILOT) وليست نسخة تشغيل معمل حقيقي.**
>
> لا تستخدم بيانات مرضى حقيقية، ولا تدخل فواتير أو قيود مالية رسمية. لا تدمج فرع PR في `main` قبل إغلاق جميع موانع النشر.

## 1) تجهيز الكمبيوتر

- Windows 11 x64، وNode.js **22** (الإصدار الذي اختبرته GitHub Actions)، وMySQL Server 5.5 محلي، وMySQL Workbench.
- اتصال إنترنت لتحميل حزم npm أول مرة. نسخة Setup الحالية **ليست حزمة تعمل دون Node/npm**.
- لا تغير إعدادات قاعدة معملك الأصلية. لا تشغّل سكربتات `DROP` ولا تستورد نسخة العمل إلى بيئة الاختبار.

## 2) إنشاء قاعدة بيانات اختبار فارغة من MySQL Workbench

افتح Workbench باستخدام حساب MySQL مخوّل بإنشاء قاعدة ومستخدم جديد، ثم نفّذ **فقط على السيرفر المحلي**:

```sql
CREATE DATABASE tlab_local_test
  CHARACTER SET utf8
  COLLATE utf8_general_ci;

CREATE USER 'tlab_sandbox'@'127.0.0.1'
  IDENTIFIED BY 'CHANGE_TO_A_NEW_UNIQUE_SANDBOX_PASSWORD';

GRANT ALL PRIVILEGES ON tlab_local_test.*
  TO 'tlab_sandbox'@'127.0.0.1';

FLUSH PRIVILEGES;
```

استبدل كلمة المرور الموضحة بكلمة مرور خاصة بالاختبار فقط قبل التنفيذ. **لا تُعد تنفيذ `CREATE DATABASE` إذا كانت القاعدة موجودة.** يجب ألا تحتوي `tlab_local_test` على أي جدول قبل التهيئة.

## 3) تنزيل نسخة Setup الخاصة بالتجربة

افتح GitHub Actions الخاص بالفرع `security/phase-1-rbac-hardening-20261119`، وافتح آخر تشغيل نجحت فيه المجموعات الثلاث (`verify` و`mysql55` و`windows-installer`). من قسم **Artifacts** نزّل:

`T-Lab-SANDBOX-PILOT-Windows-UNSAFE-FOR-PATIENTS`

الملف داخل ZIP اسمه `T-Lab_PILOT_TEST_v6.1.0.exe`. تظهر Artifacts عادةً لحسابات GitHub المسجّلة، وقد تنتهي صلاحية حفظها بعد 7 أيام. **لا تستخدم إصدارات Setup القديمة.**

عند التثبيت:
- اترك مسار `%LOCALAPPDATA%\T-Lab-Pilot-Sandbox` منفصلاً عن برنامجك الأساسي.
- MySQL Host: `127.0.0.1`، Port: `3306`.
- MySQL User: `tlab_sandbox`؛ وكلمة المرور التي اخترتها له.
- اسم قاعدة البيانات: `tlab_local_test` (بدون أي بيانات مرضى حقيقية).
- اختر كلمة مرور **جديدة وخاصة للاختبار** لحساب `developer` لا تقل عن 16 حرفًا؛ لا تستخدم كلمات مرور عملك.
- لا يبدأ البرنامج تلقائيًا لأن قاعدة الاختبار تحتاج تهيئة منفصلة أولًا.

## 4) التهيئة الأولى — مرة واحدة فقط

من قائمة ابدأ اختر:

`Initialize empty SANDBOX once`

هذا يحمّل الحزم اللازمة ويشغّل `scripts/init-sandbox.ts`، الذي يرفض قاعدة غير فارغة أو غير مسماة `_test` / `_demo`، ولا يعمل مع سيرفر MySQL بعيد. بعد نجاح التهيئة تحقق من وجود جداول MySQL في Workbench.

تُضاف تلقائيًا **بيانات اختبار وهمية فقط** بعد التهيئة: 3 تحاليل تحمل كلمة `DEMO`، و4 بارامترات بوحدة `DEMO-UNIT`، وصنفان من الكواشف برصيد متاح صفر، وحسابان محاسبيان تجريبيان وفترة مراجعة. لا تُضاف أسماء مرضى، ولا معدلات مرجعية طبية معتمدة، ولا قيود أو فواتير فعلية. العملية ترفض العمل إذا كانت جداول الكتالوج تحتوي بيانات سابقة.

**مثال معرّفات الاختبار:** `demo_lab_test_1` للتحليل، `demo_reagent_1` للكاشف، `DEMO1000` مدين، و`DEMO4000` دائن. هذه القيم ليست رموزًا صالحة لأي تشغيل معمل حقيقي.

إذا رفض السكربت التهيئة، **لا تغيّر الاسم ليشير إلى قاعدة المعمل الفعلية**. راجع رسالة الخطأ أولًا. لا تعاود استخدام نفس أمر التهيئة على قاعدة بها جداول.

## 5) التشغيل التجريبي

شغّل الاختصار `T-Lab LOCAL TEST PILOT` من قائمة ابدأ (أو الملف `start-tlab-pilot.bat` داخل مجلد الاختبار). سيقوم بعمل فحص مسبق، ثم `npm run lint` و`npm run build`، ويبدأ واجهة الإنتاج محليًا. افتح في Chrome:

<http://localhost:3007>

ادخل باسم `developer` وكلمة المرور الخاصة بالتجربة. أنشئ حسابات موظفين وهمية من إدارة الحسابات الآمنة لاختبار أدوار الاستقبال والفني والكيميائي والمحاسب والمالك.

## 6) ما يمكن تجربته فعليًا

1. تسجيل الدخول وإنشاء مستخدمين من أدوار مختلفة مع اختبار الممنوع والمسموح.
2. إنشاء مريض وهمي وطلب تحليل ثم تسجيل استلام العينة.
3. إدخال بارامترات نتائج أولية وحفظ المسودة وإرسالها للمراجعة **دون اعتماد طبي**.
4. استلام تشغيلة كواشف بالحجر ثم مراجعة مستندات الجودة وملاحظة أن الرصيد المتاح لا يزيد تلقائيًا.
5. تدقيق فروق أرصدة المخزون (قراءة فقط).
6. تدقيق تناقض الفواتير والمدفوعات ورؤوس قيود اليومية (قراءة فقط).
7. إنشاء مسودة قيد يومية متوازن وفحص رموز حساباته والفترة المحاسبية **دون ترحيل**.
8. اختبار النسخ الاحتياطي المشفّر والاستعادة **فقط في بيئة اختبار منفصلة** وفق دليل الإعدادات الرئيسي.

لا تختبر اعتماد نتيجة مريض، أو دفع/تحصيل حقيقي، أو تحرير كواشف سريرية للاستخدام. هذه الإجراءات **مغلقة عمدًا** حتى اكتمال مراجعتها.

## 7) طريقة بديلة دون Setup

يمكن تحميل الفرع على Windows من GitHub ZIP، وضع ملف `.env` محلي خاص بالاختبار في جذر المشروع، ثم تنفيذ:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows-local-pilot.ps1 -InitializeEmptySandbox -CheckOnly
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows-local-pilot.ps1
```

ملف `.env` يجب أن يحتوي على `MYSQL_HOST=127.0.0.1`، `MYSQL_DATABASE=tlab_local_test`، بيانات المستخدم التجريبي، `TLAB_ADMIN_PASSWORD` قوية، و`MYSQL_AUTO_SYNC=false`. تجنّب مشاركة ملف `.env` لأنه يحتوي على كلمات مرور.

## 8) حظر النشر النهائي

الـPilot ليس إصدارًا طبيًا أو ماليًا جاهزًا. لا تزال المديات المرجعية حسب العمر/الجنس/نوع العينة، القيم الحرجة، اعتماد الطبيب والتقارير الرسمية، المحاسبة والترحيل والتحصيل، جودة كواشف فعلية، واستمرارية العمل دون إنترنت بين أجهزة متعددة **غير مكتملة أو غير معتمدة**. تشغيل 40 شاشة في اختبار المتصفح لا يعني اجتياز كافة وظائفها التجارية.

لا تستبدل `main` ولا قاعدة بياناتك الفعلية. أرسل **نتائج اختبارك المحلي** (رسائل أخطاء بدون كلمات مرور أو بيانات مرضى) لاستكمال قبول النسخة.

## تجربة فرعين منفصلين — الإصدار التجريبي متعدد الفروع

**هذه الوظيفة ليست بعد تشغيلًا نهائيًا متعدد الفروع.**

بعد تهيئة قاعدة `tlab_local_test` الجديدة باستخدام الاختصار المخصص للاختبار، أغلق السيرفر. افتح ملف `.env` الخاص **بمجلد الاختبار فقط**، وأضف:

```env
TLAB_MULTIBRANCH_MODE=true
```

اترك `MYSQL_AUTO_SYNC=false` و`TLAB_ENABLE_LEGACY_API=false` و`HOST=127.0.0.1`. أعد تشغيل نسخة الاختبار.

1. ادخل بحساب `developer` ثم افتح **الإعدادات → إعداد الفروع وصلاحيات الموظفين**. أنشئ فرعين تجريبيين برمزين مميزين، مثل `LAB_A` و`LAB_B`.
2. من إدارة المستخدمين الآمنة أنشئ حسابي استقبال باسمين مختلفين وحساب فني، بكلمات مرور خاصة بالاختبار.
3. اربط موظف الاستقبال الأول بفرع A فقط، والثاني بفرع B فقط، والفني بفرع A فقط.
4. ادخل بحساب استقبال A، وتأكد من أن القائمة تعرض فرع A فقط. سجّل مريضًا وهميًا وأنشئ طلبًا لأحد التحاليل التجريبية.
5. ادخل بحساب استقبال B وتأكد من **عدم ظهور** مريض A وطلبه. لا يستطيع استقبال B استلام عينة طلب A.
6. ادخل بحساب الفني المرتبط بفرع A وسجل استلام عينة تجريبية للطلب؛ يجب عدم قبول الاستلام مرة ثانية.
7. راجع بيانات قاعدة الاختبار في Workbench، وخصوصًا `secure_branch_patients` و`secure_branch_requests` و`secure_branch_samples` مع أعمدة `branch_id`.

**ما هو مغلق عمدًا؟** عند تفعيل وضع الفروع المتعددة، تُحجب واجهات `/api/v2` القديمة لأنها لا تفصل البيانات على مستوى MySQL. لا تتوقع أن تعمل شاشات النتائج الطبية النهائية والفواتير والمخزون الرسمي والتقارير المجمعة بين الفروع في هذا الإصدار. لا ترفع إعداد `TLAB_MULTIBRANCH_MODE=true` على سيرفر تشغيل حقيقي.
